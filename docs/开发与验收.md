# 开发、构建与验收

## 本地开发

需要 Python 3.12、Node 22+、LibreOffice。运行时不使用在线 API。

```sh
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
python -m pip install -r requirements-dev.txt
npm ci
npm run dev
```

`INVOICE_PYTHON` 可指定 Python 路径；`INVOICE_SOFFICE` 可指定开发环境中的 soffice。发行版只查找随包 LibreOffice，不依赖系统上偶然存在的组件。

结构：`src` 为 React 界面，`electron` 为受限 IPC 和子进程管理，`core/invoice_assistant` 为纯本地处理逻辑。每个操作启动一个独立核心进程，输入一行 JSON，输出 JSON-lines 事件；取消任务终止进程树，避免 Word 子进程遗留。预览只向界面传递本机栅格图，源 PDF 中的脚本不会在页面执行。

会话数据放在 Electron `userData/session.json`，转换缓存为同目录的 `.invoice-assistant-cache`。使用新文件名原子保存会话。测试目录使用合成材料，不放入真实票据。

## 自动验证

```sh
python -m pytest -q
npm run build
npm run test:ui -- --project=browser
npm run build:core
python scripts/smoke-core.py build/core/invoice-core/invoice-core
```

Windows 打包核心文件名为 `invoice-core.exe`。浏览器测试直接调用真实 Python 核心，覆盖空状态、导入、字段编辑、预览、裁剪拆分、去重、移除、恢复、取消和导出。Browser 插件在本任务中未提供可调用能力，使用 Playwright Chromium 验证；浏览器桥接仅存在于测试代码，发行界面不能用它访问本机文件。

桌面测试用 `INVOICE_ELECTRON_E2E=1 npm run test:ui -- --project=electron`，需要能启动 Electron 的桌面环境。CI 对打包后的应用运行该测试，原生文件选择对话框由测试替换，IPC 和处理核心不模拟。

## Windows 离线 ZIP

`.github/workflows/windows-build.yml` 在 Windows x64 上构建。步骤包括依赖安装、下载并验签官方 LibreOffice MSI、提取整个 Word 运行环境、收集许可、核心测试、PyInstaller 打包、打包核心烟测、electron-builder ZIP、最终目录烟测和桌面工作流测试。失败时不上传发行包。

本地 Windows 构建：

```powershell
$env:RUNNER_TEMP = $env:TEMP
./scripts/prepare-windows.ps1
python scripts/collect-licenses.py
npm run build:core
python scripts/smoke-core.py build/core/invoice-core/invoice-core.exe vendor
npm run package:win
```

PyInstaller 采用目录模式，OCR 的 ONNX 模型、字典和动态库进入 `resources/core`。LibreOffice 及其 share/fonts 文件在 `resources/libreoffice`，许可在 `resources/licenses`。不压缩/单独剥离 DLL，不把 OCR 模型移到运行时在线下载。构建脚本参考 [PyInstaller 官方文档](https://www.pyinstaller.org/en/stable/)，Windows 构建必须在 Windows 执行。

macOS：在目标架构的 Mac 上安装依赖，将完整 `LibreOffice.app` 内容复制到 `vendor/libreoffice`（保留 `Contents`），收集许可，运行 `npm run build:core`、`npm run package:mac`。签名、公证、Mac 清洁环境验收尚未完成，不能宣称所有 Mac 架构均已支持。

## 实机验收记录

最终 Windows 实机验收尚未完成。候选包需在无 Python、Node、Office 的 Windows 10 和 Windows 11 x64 环境中：

- 完整解压、双击、确认组件检查通过。
- 断网导入普通/扫描 PDF、PNG/JPG、DOCX/DOC，多票和多页，观察单文件错误隔离。
- 拖放文件和文件夹，修订分类、月份、报销人、票号、日期、金额和裁剪范围。
- 验证同号重复、字段冲突、去重后移除首项、拆分重叠阻断。
- 取消导入和导出、关闭重启恢复；原文件内容哈希保持不变。
- 逐页检查 A4、长票单页、两票限制、附件半页、页码和书签。
- 在 Excel 或其他表格软件中打开六列明细，检查中文、票号前导零和 20 位完整值；核对张数、金额及分类统计。
- 实际打印至少各类一页，检查二维码、印章、备注和票号可读。

## 界面检查依据

可访问的依据是仓库里的设计文字：单页顶栏、选择文件/文件夹、可编辑报销信息、拖放区、明细表和底部导出。已选参考截图留在本机私有目录，不能在本云端读取，未宣称逐像素匹配。界面没有预填姓名、报销月份或示例票据。

检查点：① 白色主界面与浅蓝拖放区；② 顶栏文件操作和右侧信息字段；③ 明细列、状态及修订入口；④ 空状态和导出禁用；⑤ 核对原件、裁剪交互和自定义类别；⑥ 窄屏字段/底栏折行且表格横向滚动。截图通过 Playwright 获取后使用 view_image 目视检查；未新增营销页面或改变工具流程。
